# 子 Agent 发现自动吸收进长期记忆 — 问题分析

> 生成时间：2026-07-23
> 来源：三元协同流水线遗留问题讨论

---

## 一、现状

```
先生 → 主 Agent spawn 子 Agent（探索/落实验证等）
       ↓
子 Agent 干活 → 输出结果
       ↓
session 关闭，cleanup: delete ← 🚩 所有发现随之消失
       ↓
主 Agent 有机会手动读结果，提取有价值信息写入 long-term/
       ↓
但没有任何机制保证这件事一定会做
```

当前结构：**子 Agent 没有写入长期记忆的能力，主 Agent 也没有强制机制来提取子 Agent 的发现。**

---

## 二、具体痛点

### 痛点 1：发现靠"记不记得"

子 Agent 的输出只在 session 上下文中存在。session 关闭后，只剩主 Agent 在对话中的转述。如果主 Agent 忘记提取或当时觉得"不重要"，信息就永久丢失。

**例子**：今天下午的验证子 Agent 检查了 12 项全部通过。这 12 项检查标准和结论没有任何地方归档。下次再设计类似方案时，没法自动回顾上次验证的历史。

### 痛点 2：没有"值得记"的信号

子 Agent 的输出里：
- 哪些只是执行日志？
- 哪些是值得保留的发现？
- 哪些是环境状态的快照？

目前没有任何信号机制来区分。要么全丢了，要么全手动摘。

### 痛点 3：回写路径不清晰

子 Agent 安全约束：
- 没有 `edit`/`write` 权限（合理的安全设计）
- 即使发现值得记的东西，也没法自己写
- 唯一路径：子 Agent 输出报告 → 主 Agent 读 → 提炼 → 写 long-term/

这条路径依赖主 Agent 的"自觉性"，没有任何强制或半自动机制兜底。

### 痛点 4：缺少被动采集

即使主 Agent 忘了提取，也没有兜底方案：
- Reflector 每日 03:00 扫描的是 long-term/ + handoff/
- 子 Agent 的输出不在扫描范围内
- 所以没有"回收站"机制

---

## 三、三元协同流水线覆盖了什么

三元协同流水线只改进了**审查环节**的结果留存：

| 子 Agent 类型 | 现状 | 三元协同改进了吗 |
|:------------:|:----:|:--------------:|
| 探索子 Agent（只读探索） | session 关闭即丢 | ❌ 没变 |
| 落地验证子 Agent（机械核对） | session 关闭即丢 | ❌ 没变 |
| ~~临时验证子 Agent~~ | ~~结果丢~~ | ✅ 已废弃，改 handoff/ |

其他两种子 Agent 的发现流向完全没有改变。

## 四、待解决问题清单

| 编号 | 问题 | 影响 | 优先级 |
|:----:|------|:----:|:-----:|
| 1 | 子 Agent 发现的值得记的信息随 session 关闭丢失 | 长期记忆不完整 | 🟡 |
| 2 | 没有机制自动识别输出中的"值得记"内容 | 遗漏风险 | 🟡 |
| 3 | 子 Agent 没有写长期记忆的权限（安全限制） | 回写路径阻塞 | 🟢 |
| 4 | 主 Agent 提取子 Agent 发现缺乏流程保证 | 依赖自觉性 | 🟡 |
| 5 | 缺少被动采集机制（Reflector 不扫描子 Agent 输出） | 无兜底 | 🟢 |

## 五、可能的解决方向（待讨论）

### 方向 A：子 Agent 输出缓冲区

子 Agent 任务结束时，无论任务成功与否，都写一个标准格式的 `findings` 文件到 `work/` 目录。
- 格式：结构化摘要（发现内容、置信度、来源 session）
- 主 Agent 启动时或 Reflector 扫描时读取 `work/` 目录
- 有价值的自动提取到 long-term/，无价值的过时清理

### 方向 B：主 Agent 强制提取机制

每次子 Agent 完成后，主 Agent 自动调用 `sessions_history` 读取完整输出：
- 用预定义规则（或 LLM 判断）筛选值得记的内容
- 写入 long-term/ 对应文件
- 记录提取状态避免重复

### 方向 C：Reflector 兜底扫描

Reflector 每日扫描时，增加对 `work/` 或子 Agent 输出目录的检查：
- 扫描未处理的 findings 文件
- 确定有价值 → 推荐写入 long-term/
- 确定无价值 → 标记已处理或删除
- 不确定 → 在治理报告中列出供先生判断
