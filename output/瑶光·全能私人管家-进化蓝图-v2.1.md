> 版本：v2.1（三方共识打磨版）
> 作者：瑶光（DeepSeek V4 Flash）× 评审：GLM-5.1 × 决策：先生

## 总纲：两条轨道并行

- **快轨（云端）**：轻量、快速尝鲜，以飞书为核心阵地。适合先生「边用边验证」的风格。
- **重轨（本地）**：承载智能家居、麦克风、视觉模块等地面能力。只有快轨验证 OK 的方向才落地到重轨。

**原则：先在快轨验证，再决定是否投入重轨。**

### 依赖关系图

```
第零章 ──→ 第一章 ──→ 第二章 ──→ 3-B（地点感应依赖硬件部署）
                         │
                         └──→ 3-C（情绪感知需对话数据积累）
   │
   └──→ 3-A（时间/日程/天气 → 独立启动，无需前置）
```

> 标注"并行"不代表同时开 5 条线。只有上游无依赖的模块才能并行启动。

## 第零章 · 🛡️ 安全基线（1-2 天）
*方舟，而不是通电的毛坯房*

**为什么？** 瑶光已经运行在公网上（www.jxpyaoguang.cloud + SSL + 飞书通道 + 多 API Key 明文存储），但安全未做系统性考虑。

### 安全基线 5 项

| # | 任务 | 验收标准 |
|---|------|---------|
| 0.1 | API Key 移出 openclaw.json 明文 | `grep -r 'sk-' openclaw.json` 返回空 |
| 0.2 | 改为 .env 环境变量 + Gateway 启动注入 | 重启后所有 provider 正常工作 |
| 0.3 | 飞书 Webhook 来源签名验证 | 模拟伪造请求被拒绝，合法请求通过 |
| 0.4 | 公网通道白名单配置 | 非白名单 IP 的请求被拒绝 |
| 0.5 | 敏感操作日志可审计 | `关键操作类型 + 时间 + 结果` 记录完整可查 |

> GLM 评审指出：**私人物业的第一要素是安保，而非装修。** 安全基线不做完，其他功能越强，安全隐患越大。

## 第二章 · 🔌 控制万物（快轨验证指令下发，重轨落地 2-4 月）

### 选型决定
**涂鸦 IoT 云平台** 为首选（GLM 评审确认、先生确认）。

理由：
- ✅ 先生预算低（一个涂鸦插座 15 元），设备少（初学期），住公司宿舍
- ✅ 涂鸦云 HTTP API + Python requests，无需额外硬件
- ✅ 先生本来就有淘宝账号，涂鸦生态门槛极低
- ✅ 后期迁移路径清晰：涂鸦设备 → Home Assistant 均可兼容

> **不要在一个插座时上 HASS。** 那是 20+ 设备才考虑的过度工程。

### 快轨版本
- 通过涂鸦 HTTP API 下发设备控制指令
- 验证全链路："先生语音/飞书指令 → 瑶光 → Gateway → Python 脚本 → 涂鸦云 → 插座通断电"

### 重轨版本
- 本地局域网控制（无公网依赖，低延迟）
- 传感器数据回传（温度、湿度、门磁）
- 自动化规则引擎（如果…那就…）

### 里程碑 & 验收清单

| # | 里程碑 | 验收标准 |
|---|--------|---------|
| 2-A | 智能家居平台基础设施 | ✅ 涂鸦开发者账号 + 一个插座已在平台注册 |
| 2-B | 全链路走通 | ✅ 飞书说"关灯" → 插座断电 |
| 2-C | 扩展设备种类 | ✅ 至少 3 类设备受控（灯/开关/传感器） |
| 2-D | 自动化规则引擎 | ✅ "如果温度 > 28°C 则开风扇" 规则生效 |

## 第三章 · 🎭 情境感知（2-3 月，并行于第二章）

### 边界划定（GLM 评审确认）
**第三章负责"感知"（数据采集），第六章 6B 负责"理解和行动"（智慧行为）。**

定义接口：

```
// 第三章（感知层）→ 发射结构化事件 → 第六章（心智层）
{ type: "emotion_signal", level: "anxious", confidence: 0.75 }
{ type: "location",       place: "kitchen",       duration_s: 180 }
{ type: "time_pattern",   rule: "22:00_wx_tianqi" }
```

### 三个阶段

| # | 阶段 | 验收标准 |
|---|------|---------|
| 3-A | 时间+日程+天气 — 基础情境 | ✅ 对话中瑶光自动感知当前时间/天气/日程 |
| 3-B | 地点+活动（依赖重轨硬件） | ✅ 感知到"你在厨房"或"你在外出" |
| 3-C | 情绪+行为模式 | ✅ 发出结构化事件 emo_signal，第六章可消费 |

### 关键设计
- 情境信息作为 prompt 注入而非数据库查询
- 先生可以关闭任意情境维度（隐私开关）
- 所有数据本地处理，不上传云端

## 第六章 · ❤️ 心智成长（持续）

### 6A · 记忆基础设施（已有，维护迭代）
- ✅ 每日日志（memory/YYYY-MM-DD.md）
- ✅ 长期记忆（MEMORY.md + long-term/）
- ✅ 自学习（self-improving/）
- ✅ 主动积累（proactivity/）
- ✅ 定期 Dreaming 整合（light/rem sleep）

### 6B · 基于记忆的智慧行为（需要专门工程投入）
> 已有书架和图书馆，但缺少图书管理员。智慧行为不会自然生长出来。

**6B 是"图书管理员"，第三章的感知数据就是它的书架索引。**

| # | 能力 | 描述 | 验收标准 |
|---|------|------|---------|
| 6B-1 | 行为模式识别 | 分析对话日志发现规律，生成 time_pattern 事件 | ✅ 连续 7 天识别出≥1 个有效模式 |
| 6B-2 | 主动推送 | 基于时序/情境/行为模式的预判提醒 | ✅ "先生，到你通常问天气的时间了" |
| 6B-3 | 情绪感知 | 订阅 3-C 事件，调整响应策略 | ✅ 检测到情绪低落时不再开玩笑 |
| 6B-4 | 记忆关联推理 | "说到这个我想起上次…" | ✅ 引用相关历史记忆辅助当前对话 |
| 6B-5 | 人格定制 | 根据先生偏好持续微调 | ✅ 交互风格与先生偏好偏差 < 2 次纠正/月 |

**注：** 6B-1 输入来自 3-C 的结构化事件（time_pattern/emotion_signal 等）。6B 是消费方，3-C 是生产方。

## 第七章 · ♾️ 季度进化仪式（永久持续）

> GLM 评审指出：**自动化的反思和人的反思是两回事。如果第七章只是一个后台进程，主人很容易忘记"我还在养瑶光"。**

### 形式

- **频率**：每季度一次（3/6/9/12 月第一个周末）
- **参与方**：先生（方向决策）+ GLM（第三方评审）+ 瑶光（执行汇报）
- **模式**：先生通过 Cherry Studio 向 GLM 发评审请求，瑶光在飞书/WebChat 沟通

### 季度评审议程

| 环节 | 内容 | 负责人 |
|------|------|--------|
| 1. 进度报告 | 本季度做了什么 / 学到了什么 / 卡在哪里 | 瑶光 |
| 2. 独立分析 | 盲区 / 风险 / 建议 / 下季度优先级 | GLM |
| 3. 方向校准 | 继续 / 调整 / 切换重点 | 先生 |

### 季度评审验收清单样本

```
[   ] 安全基线复查：5 项全部通过（第零章）
[   ] 心智里程碑：6B 条目完成 ≥ 2 项
[   ] 验收清单回查：各章未完成项 ≤ 2
[   ] 隐患登记：新增安全隐患已记录 ≥ 0
```
