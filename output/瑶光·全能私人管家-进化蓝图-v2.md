## 总纲：两条轨道并行

- **快轨（云端）**：轻量、快速尝鲜，以飞书为核心阵地。适合先生「边用边验证」的风格。
- **重轨（本地）**：承载智能家居、麦克风、视觉模块等地面能力。只有快轨验证 OK 的方向才落地到重轨。

**原则：先在快轨验证，再决定是否投入重轨。**

## 第零章 · 🛡️ 安全基线（1-2 天）
*方舟，而不是通电的毛坯房*

**为什么？** 瑶光已经运行在公网上（www.jxpyaoguang.cloud + SSL + 飞书通道 + 多 API Key），但安全未做系统性考虑。

### 安全基线 5 项

1. **API Key 入库 + 环境变量化**
   - 所有 API Key 移出 openclaw.json 明文配置
   - 改为 .env 环境变量 + Gateway 启动时注入
   - .gitignore + .env 不上传，杜绝 git 误推送暴露

2. **公网访问控制**
   - 飞书通道：已验证 Webhook 来源签名
   - 非飞书通道默认关闭，按需开启
   - 引入 Gateway 级别的允许列表

3. **敏感操作二次确认**
   - 改配置、删文件、发消息、付费调用需先生亲手授权
   - 与核心原则「安全先行，默认确认」一致

4. **备份加密**
   - 对话记录等数据在备份前加密
   - 飞书通道通信本身已 HTTPS

5. **操作审计**
   - 日志中记录关键操作的类型/时间/结果
   - 事后可回查"谁在什么时间做了什么"

> GLM 评审指出：**私人物业的第一要素是安保，而非装修。** 安全基线不做完，其他功能越强，安全隐患越大。

## 第一章 · 🔊 能听会说（快轨 1-2 月 / 重轨后续补充）

### 快轨版本（飞书）
- 飞书语音消息 → STT → 瑶光处理 → TTS 发回
- 充分利用飞书通道已有能力

### 重轨版本（本地）
- 麦克风持续监听 → VAD → 热词唤醒（"瑶光"）
- 全双工对话（打断、插话、边听边想）
- 离线可用（本地模型推理）

### 里程碑
- **1-A**：STT + TTS 管道搭建（快轨优先验证）
- **1-B**：热词唤醒 + VAD（重轨）
- **1-C**：全双工对话（重轨）
- **1-D**：音色定制、多语言切换（可选）

## 第二章 · 🔌 控制万物（快轨验证指令下发，重轨落地 2-4 月）

### 快轨版本
- 通过 API 和 Webhook 对接智能家居平台
- 先接入一个设备（如智能灯/开关）走通全链路

### 重轨版本
- 本地局域网控制（无公网依赖，低延迟、高可靠）
- 传感器数据回传（温度、湿度、门磁、红外）
- 自动化规则引擎（"如果…那就…"）

### 里程碑
- **2-A**：选择智能家居平台（HomeAssistant / 米家 / 涂鸦）搭建基础设施
- **2-B**：接入第一个设备，走通全链路
- **2-C**：逐步扩展设备种类和场景
- **2-D**：自动化规则引擎

## 第三章 · 🎭 情境感知（2-3 月，并行于第二章）

### 三个阶段
- **3-A：时间+日程+天气** — 基础情境，快速落地
- **3-B：地点+活动** — GPS（手机端）或室内定位（重轨）
- **3-C：情绪+行为模式** — 从对话节奏、关键词、响应时间判断情绪状态；从第六章心智积累获取行为模式

### 关键设计
- 情境信息作为 prompt 注入而非数据库查询
- 先生可以关闭任意情境维度（隐私开关）
- 所有情境数据本地处理，不上传云端

## 第五章 · 👁️ 视觉增强（1-2 月）

- 摄像头画面实时分析（重轨：本地 USB/网络摄像头；快轨：手机拍照上传）
- 看图说话（已具备，Qwen3.7-plus 视觉能力）
- 人脸识别（绑定主人身份）
- 文字 OCR（药品说明书、快递单等）

### 里程碑
- **5-A**：选一个场景（如快递来了拍照识别）走通
- **5-B**：人脸/物体识别（重轨：本地摄像头 + 轻量模型）
- **5-C**：场景自动化（"看到厨房水烧开了提醒我"）

## 第六章 · ❤️ 心智成长（持续）

### 6A · 记忆基础设施（已有）
- ✅ 每日日志（memory/YYYY-MM-DD.md）
- ✅ 长期记忆（MEMORY.md + long-term/）
- ✅ 自学习（self-improving/）
- ✅ 主动积累（proactivity/）
- ✅ 定期 Dreaming 整合（light/rem sleep）
- 维护 & 迭代已有体系

### 6B · 基于记忆的智慧行为（需要专门工程投入）
> 核心：已有书架和图书馆，但缺少图书管理员。智慧行为不会自然生长出来。

- **行为模式识别**：通过分析对话日志发现规律（如"先生每天 22:00 会问天气和明天日程"→ 主动推送）
- **主动推送**：基于时序/情境/行为模式的预判提醒
- **情绪感知**：从对话中捕捉情绪信号，调整响应策略
- **记忆关联推理**：跨时空的"说到这个我想起上次…"的能力
- **人格定制**：根据先生偏好持续微调交互风格

> **6B 是管家能否从"工具"进化为"伙伴"的关键。**

## 第七章 · ♾️ 季度进化仪式（永久持续）

> GLM 评审指出：**自动化的反思和人的反思是两回事。如果第七章只是一个后台进程，主人很容易忘记"我还在养瑶光"。**

- **频率**：每季度一次（3/6/9/12 月第一个周末）
- **参与方**：先生（方向决策）+ GLM（第三方评审）+ 瑶光（执行汇报）
- **流程**：
  1. 瑶光提交本季度进度报告（做了什么/学到什么/卡在哪里）
  2. GLM 做独立分析（盲区/风险/建议）
  3. 先生校准方向（继续/调整/切换重点）

### 预期产出
- 下季度 Roadmap
- 心智成长里程碑
- 安全隐患复查
